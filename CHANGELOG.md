## [1.1.0] — 2026-10-19

### Added

- **Новое site-независимое ядро `core.py`** — всё, чему не нужно знать про
  конкретный сайт: конфиг, HTTP-слой, разбор Kodik (`POST kodikplayer.com/ftor`
  для обоих путей — `type=season` и `type=seria`), скачивание (`download_hls`,
  `hls_file_ok`), политика сабов, оркестрация пула (`run_title`): выбор группы,
  папка, файл-маркер, resume-проверка, ThreadPool по сериям, отчёт.
- **Слой адаптеров сайта** за единым интерфейсом:
  - `site_adapter.py` — `EpisodeRef` / `TitleInfo` / `SiteAdapter` / `get_adapter`,
    выбор по домену; чистый интерфейс без логики;
  - `site_me.py` — `old.yummyani.me`: разбор страницы тайтла, `page_id`,
    группировка озвучек/сабов (чистка префиксов `Озвучка `/`Субтитры `),
    фильтр Kodik-iframe;
  - `site_tv.py` — `yummyanime.tv`: handshake переиспользует `tv_adapter.py`
    (`TvOpener` / `tv_slots` / `SerialSession`), разбор `data-player-anime-id`,
    `data-player-slot/title`, переводов и сезонов kodik-serial.
  Хрупкие парсеры стали **чистыми функциями** (принимают сохранённый
  текст/JSON → возвращают данные, без сети), поэтому тестируются на фикстурах.
- **Тесты на фикстурах в `tests/`** — 153 теста, без сети и внешних зависимостей:
  парсеры обоих сайтов на реальных сохранённых страницах и ответах API
  (`tests/fixtures/`), контракт адаптеров, повтор HTTP-слоя, выбор httpx-бэкенда.
  Запуск одной командой: `py -3.9 tests\run_tests.py`.
- **Альтернативный HTTP-бэкенд сегментов на `httpx`** — убирает кастль
  «urllib → curl.exe»: один keep-alive клиент на пул, `follow_redirects`
  (ради 302 на `nova.cloud.solodcdn.com`), h2 при наличии пакета `h2`,
  запись сегмента стримом на диск. Переключается `config.json`
  (`"http_backend"`) или флагом `--backend auto|httpx|urllib`.

### Changed

- `yummy_dl.py` сокращён с **863 до 364 строк**: остались меню, CLI и реэкспорт
  публичного API. Поведение CLI, тексты вывода, имена файлов-маркеров
  (`_озвучка.txt` / `_субтитры.txt`) и путь `downloads/<Название>/Серия NN.mp4`
  не изменились.
- **Публичный API для `yummy_gui.py` не изменился**: все имена, которыми
  пользуется GUI, остались в `yummy_dl.py` с той же сигнатурой и поведением —
  они реэкспортируются из `core.py` и адаптеров.

### Removed

- Из репозитория удалены остатки прежней версии: каталог `_legacy/`
  (боты и служебные скрипты) и `docs/CHANGES_FORK.md`. Код остался в истории
  коммитов.

### Fixed

- Одиночный обрыв соединения (WinError 10054 «удалённый хост принудительно разорвал
  подключение») больше не прерывает работу: `http_get` / `http_post` повторяют
  запрос при **сетевом** обрыве (3 попытки, паузы 0.5 / 1.5 с). HTTP-статусы
  (404/4xx/5xx) не повторяются.

### Notes

- `httpx` — **опциональная** зависимость: без неё код полностью работоспособен,
  `auto` сам откатывается на старую цепочку `urllib → curl`. Ставить нужно,
  только если системный `curl.exe` нерабочий или хочется h2.
- 1.1.0 не меняет способ установки и запуска: тот же `Start_GUI.cmd`, тот же CLI.

## [1.0.8] — 2026-10-19

### Added

- Альтернативный HTTP-бэкенд сегментов на `httpx` — убирает кастль
  «urllib → curl.exe». Прежний путь **не тронут и работает как раньше**.
  - выбор бэкенда: `auto` (httpx, если пакет есть, иначе urllib→curl) |
    `httpx` (явно; без пакета — понятная ошибка, НЕ молчаливый откат) |
    `urllib` (только старая цепочка);
  - источник значения — `core.CFG["http_backend"]` (по умолчанию `auto`)
    либо CLI-флаг `--backend auto|httpx|urllib` в `yummy_dl.py`;
  - один лениво созданный `httpx.Client` на модуль, переиспользуется всеми
    потоками пула, потокобезопасен, `follow_redirects=True` (ради тех самых
    302 на `nova.cloud.solodcdn.com`), `http2=True` при наличии пакета `h2`,
    лимит соединений не меньше числа потоков (пересоздаётся при росте),
    те же `User-Agent`/`Referer` и тот же timeout, что и у urllib-пути;
  - в httpx-режиме сегмент пишется **стримом на диск** (`client.stream` +
    чанки по 64 КБ), а не буферизуется в памяти — в пуле из 8 потоков это
    экономит до десятков МБ;
  - отсутствие `httpx` даёт понятное сообщение (`py -m pip install
    "httpx[http2]"`), а не `ImportError` в неожиданном месте;
  - `httpx[http2]>=0.24` добавлен в `requirements.txt` как **опциональная**
    зависимость: без него код полностью работоспособен (`auto` → urllib→curl).
- `tests/test_http_backend.py` — 37 тестов без сети: выбор бэкенда (auto с
  httpx и без, явный urllib, явный httpx без пакета, мусор в конфиге),
  постройка клиента (redirect'ы, лимиты, переиспользование, деградация
  h2 → HTTP/1.1 без пакета `h2`), httpx-путь на подставном клиенте
  (заголовки, байты, ошибки HTTP), стриминг пишет файл с тем же SHA-256,
  `--backend` разбирается и доходит до `seg_dl.set_backend`, и отдельные
  тесты, что urllib-путь и его откат на curl не изменились.

### Fixed

- На машинах, где системный `curl.exe` нерабочий (`CRYPT_E_REVOCATION_OFFLINE` —
  Schannel не может проверить CRL), откат сегмента на curl был мёртвым:
  доступ к CDN терялся целиком. Теперь есть живой путь без внешних программ.

### Notes

- Живая сверка 1.0.8 (серия 1, `AniLibria`, 720p, первые 20 сегментов):
  **20 из 20 сегментов совпали по SHA-256 и по размеру** между `urllib` и
  `httpx`. httpx быстрее в ~2.2 раза на сегмент (0.55 с против 1.21 с) —
  за счёт keep-alive: одно соединение на пул вместо TCP+TLS на каждый сегмент.
- HTTP/2 включён в клиенте (`h2` установлен), но CDN `cloud.solodcdn.com`
  по ALPN отвечает `HTTP/1.1` — h2 с ним не согласуется. На других хостах
  может включиться, но выигрыш тут всё равно даёт keep-alive.

## [1.0.7] — 2026-10-19

### Fixed

- Одиночный обрыв соединения больше не показывается пользователю красной ошибкой:
  `core.http_get()` / `core.http_post()` повторяют запрос при **сетевом** обрыве —
  `ConnectionResetError` (WinError 10054 «удалённый хост разорвал подключение»),
  `ConnectionAbortedError`, `BrokenPipeError`, `socket.timeout` / `TimeoutError`,
  `http.client.RemoteDisconnected`, а также `urllib.error.URLError`, у которого
  `.reason` — одно из перечисленного.
  Три попытки всего, паузы 0.5 с и 1.5 с между ними (суммарно ≤ 2 с, GUI не «висит»).
  HTTP-статусы (404/4xx/5xx) и любые другие исключения **не** повторяются: это ответ
  сервера, а не разрыв канала, и повтором он не лечится. `api()` отдельного повтора
  не имеет — он идёт через `http_get()` и покрывается автоматически.
  После исчерпания попыток поднимается тот же тип исключения, что и раньше (свой
  класс не заводим), но с текстом вида `3 попытки, последняя ошибка: ...`.

### Added

- `tests/test_http_retry.py` — 19 тестов на повтор HTTP-слоя без сети
  (сеть замокана на `core._urlopen_once`, `time.sleep` тоже замокан): успех с первого
  раза, два обрыва + успех на третьей попытке, `URLError(reason=ConnectionResetError)`,
  `socket.timeout`, `RemoteDisconnected`, исчерпание попыток (сообщение содержит число
  попыток и тип исключения прежний), `HTTPError` 404/500 — ровно одна попытка,
  постороннее исключение (`ValueError`) — одна попытка, симметричность backoff,
  `binary=True` и прохождение `api()` сквозь повтор.

### Notes

- Регрессом рефакторинга это не являлось: `http_get`/`http_post`/`api` в `core.py`
  совпадают со старым монолитом посимвольно, набор HTTP-заголовков и SSL-контекст
  те же. Виновник — остаточный драйвер Sangfor (`SangforTcpDrv.sys`) в TCP/WFP-пути:
  при отключённом VPN-туннеле он продолжает работать и рвёт первое соединение после
  простоя (воспроизведено: после 75 с простоя 2 попытки из 3 падали с WinError 10054
  на TLS-handshake, третья — 0.7 с OK). Повтор — правильная реакция на это, а не
  обход: ретраится только обрыв, ответы сервера по-прежнему показываются как есть.

## [1.0.6] — 2026-10-19

### Fixed

- Битые обрывки серий больше не пропускаются при resume: существующий файл
  на «уже есть - пропуск» теперь проверяется `hls_file_ok()` (ffmpeg открывает
  файл: нет `Duration` / есть `Invalid data` → неиграбельный обрывок).
  Сломанный файл удаляется и качается заново («повторно качаю: …»), вместо
  пропуска по порогу «больше 10 КБ», из-за которого получались битые mp4.
- Проверка итога качки добавлена и после скачивания (сегментный путь и прямой
  ffmpeg, CLI и GUI): неиграбельный файл не переименовывается в финальный,
  серия завершается ошибкой с причиной или качается заново.

## [1.0.0] — 2026-10-03

Первый версионированный релиз форка (база — upstream
[foxycuter2-ai/YummyDownloader](https://github.com/foxycuter2-ai/YummyDownloader)).

### Added

- GUI `yummy_gui.py` (tkinter): ссылка → Проверить → озвучка/качество/серии/
  франшиза → Скачать/Отмена; прогресс серий и общий (МБ, МБ/с); спинбокс
  «Потоки серий» 1–8; кнопка «Установить зависимости»; фикс Ctrl+V в русской
  раскладке; докачка повторным «Скачать».
- `seg_dl.py`: параллельная качка HLS-сегментов (пул 8, до 32), ретраи 3x +
  backoff, urllib → curl-fallback, склейка `ffmpeg -f concat -c copy` без
  перекодирования, fallback на прямой `ffmpeg -c copy`.
- `tv_adapter.py`: поддержка `yummyanime.tv` — handshake карточки, слоты
  Alloha/Kodik, переводы × сезоны/серии serial-iframe Kodik, резолв серий
  через POST `/ftor`; авто-детект `.tv`-ссылок в CLI и GUI.
- `Setup_Python.cmd`: автопроверка/установка Python 3.9+ (winget → установщик
  python.org) + `pip install -r requirements.txt`; `Start_GUI.cmd`: запуск GUI
  в один клик.
- Версионирование: `VERSION`, `CHANGELOG.md`, переписанный `README.md`.

### Changed

- `yummy_dl.py`: параллельные серии (`workers=4`, `--workers 1–8`;
  `--segs` / `--seg-workers 1–32`); `download_hls()` с сегментным путём и
  прогресс-колбэком; `tv_grab()` для `.tv`; строка `потоки: серии=N, сегменты=M`.

### Known limitations

- Плееры Alloha/CVH не реализованы (только точка входа при handshake).
- `.tv` напрямую без VPN; при блокировке Kodik на egress нужны DIRECT-исключения.
- Франшиза (`all_seasons`) — только для `old.yummyani.me`.
- Потолок качества 720p, только Kodik — как в upstream.
